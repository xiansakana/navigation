# 模块授权和数据范围

入口：权限管理 → 模块与数据范围。角色页配置功能权限，本页配置模块开关、默认成员功能权限和数据范围，两者必须同时满足。策略保存在共享 SQLite 的 RBAC 配置中，复用版本冲突检测。

## 原有数据

首次加载把原有登录成员默认权限迁入可编辑配置。原有个人数据仍绑定原 user_id；博客公开范围、共享服务实例、已有角色权限保持原状。不自动开放跨账号数据，也不复制、迁移、合并或重新分配旧数据。

游客已有的角色、停用状态和首次迁移后明确授予的权限不会在后续同步时被覆盖。个人功能仍要求真实登录；数据授权不能代替登录、执行项目白名单或功能权限。

## 数据范围

- 个人模块：记账、知识库、命理、股票（含量化与梭哈）、Chain、Codex CLI、QQ Codex，默认使用自己的数据。可分别关闭本人读取或修改权限。
- 指定用户共享：选择数据所属账号，将该模块的数据以只读或可修改方式授权给指定用户或角色。授权范围为该账号在此模块中的全部数据，不能把一份授权理解为仅共享单个账本或笔记。
- 团队空间：空间绑定明确的数据所属账号，授权仍按模块单独设置。需要独立团队数据时，先在用户管理中创建专用团队账号，再绑定空间。多个空间绑定同一账号时指向同一份数据；空间名称不是额外的存储分区。
- 博客：默认保留按文章可见范围展示的动态；选择指定账号或团队空间时，只展示该账号的文章。共享范围的读授权允许查看该账号私密文章，应明确知情后授权。实际修改还需相应功能权限和数据修改授权。
- 共享服务：资源管理、通知管理、Torn 压价/公司监听、抄底监控、思源、NapCat、PicList、AList 等使用共享实例。需要隔离时，先部署独立上游实例并在 Portal 的 services 中注册不同服务 ID，再在本页绑定和授权。不能把同一个全局实例切换成多份个人配置。外链服务自身的账号、目录及实例由上游管理。

浏览器顶部“数据范围”选择只显示已授权范围，选择保存在浏览器会话 Cookie 中，每次请求重新校验。切换后重载页面，不把旧页面的数据混入新范围。Cookie 或请求头不是授权凭证，伪造范围不会绕过授权。账号切换后旧选择也会重新校验；已撤销的选择不会静默回退到其他账号。

## 服务实例

独立实例使用现有代理配置，包括 internalUrl、upstreamPathPrefix、认证配置等。相应上游必须与原模块兼容，且只在可信内部网络可达。登记实例不等于部署实例，也不会自动创建容器或迁移第三方服务的数据。

思源编辑器、NapCat 等交互管理界面可能通过 WebSocket 写入，因此访问管理界面需要数据修改授权；仅只读的分享应使用上游提供的只读发布服务。普通 WebSocket 连接按修改授权检查。抄底监控还保留原账号所有者校验，不能仅靠赋予 Portal 查看权限绕过；其他用户需独立实例或单独升级该上游的多用户模型。

Codex 的数据范围仅管理会话、待办和设置等数据，不自动创建独立 OS 沙箱。代理操作他人的会话时，执行项目必须同时出现在操作人和数据所属账号的白名单中。服务器全量历史不会因选择一个共享账号而扩大到全部用户。执行项目目录、服务器账户及外部服务仍需管理员独立配置。

## 安全与审计

- 服务端先校验操作者及其功能权限，再按授权的数据所属账号查询；不接受正文中的 userId 作为身份。
- 查看和修改分开授权；下载可生成工作器凭据的 GET 接口也按修改检查。
- 管理员的通配功能权限不自动授予其他账号的数据范围。原有博客管理、服务器全部会话等明确的跨账号功能权限仍独立受控。
- 授权撤销、数据所属账号停用、模块停用后，后续请求重新判定。知识库和 Chain 的后台授权也检查模块开关；Codex 执行器检查对应模块状态。撤销共享授权不会删除已被所属账号接受的任务或其结果。
- 修改请求记录操作者 ID、数据所属账号 ID、模块、范围、接口路径、时间和 HTTP 状态到 data_access_audit；不记录正文、Cookie 或密钥。
- 策略保存需 admin:data-policy:edit；只读需 admin:data-policy:view，并仍要求进入后台的权限。旧页面保存遇到策略版本变化会返回 409。

测试覆盖真实 HTTP 鉴权、代理身份头覆盖、只读阻止写入、共享账号边界、实例选择、授权撤销、停用账号、并发版本冲突、跨站写入和操作人审计。新增模块应注册到统一目录并接入数据范围检查，不能仅提供管理页配置而不在 API 执行。
