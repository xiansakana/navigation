# 记账模块

首页服务列表提供记账入口，收支概览仅在 `/bookkeeping/` 内展示，首页不请求账单数据。完整页面由 Portal 自身提供，不需新增进程或反向代理。支持 PC 分栏及手机底部导航、深浅主题、明细筛选/分页、记一笔/编辑/删除、分类与每日收支、CNY 月预算、资产分组、多币种账户、信用额度/账单日/还款日、余额调整、iCost XLSX 导入预览与导出。

## 权限和存储

权限集中定义于 `portal/src/rbac.js` 的 `bookkeeping:*` 条目，包含查看、账单编辑、资产查看/编辑、分类查看/编辑、导入、导出、预算和汇率设置。每一项含首页下的 permissionPath。管理员自动获得权限，普通用户由管理员分配；游客无法访问。页面、API 和首页均检查权限。SQLite 的 bookkeeping 表按 Portal userId 隔离，客户端提交的用户 ID 不参与数据归属。

## 迁移口径

- iCost 查看用导出没有完整资产初始余额与余额调整历史，不可直接累加还原资产。历史导入记录 `affects_balance=0`；截图账户余额为初始基准，之后手工新增的记录联动余额。修改或删除历史导入账单不改变基准，应通过“核对余额”调整。
- 账户快照 JSON 可在导入界面附带上传，仅创建尚不存在的账户；已有账户余额不会被覆盖。快照数组字段为 `name, group, currency, balance, included, creditLimit, billDay, dueDay, note, snapshotAt`。负余额表示负债；不计入账户在原币和折算总资产中均排除。
- 跨币种历史转账只有一个金额，无法还原到账额。保留原币和原始字段，新跨币种转账必须明确到账额。汇率统一表示一个原币兑换多少 CNY；自动、手动和缓存均缺失时不显示折算总数。
- 支出/已报销计入支出；退款入账/报销入账冲减支出；收入计入收入。转账/还款/借出/收回/余额调整不计入收支，手续费计入支出。原单的退款与优惠是辅助信息，不再次冲减。
- 导入按字段内容哈希和相同行出现次数去重，重复上传不会重复记账；内容修改后重新上传属于新记录，请在页面中编辑原记录。错误行会阻止整个导入，不静默丢弃。预览只存内存，15 分钟失效，按用户绑定。
- 导入保留原始行和图片来源链接作为私有数据，不自动访问远程图片。XLSX 导出使用 iCost 列顺序，供查看和迁移，不包含原始图片链接、跨币种到账额或账户余额，不能视为完整备份或承诺能恢复到 iCost。

CLI 可在明确指定用户后导入，个人文件不得进入 Git：

```powershell
node scripts/import-icost.mjs --user admin --file '<iCost.xlsx>' --accounts '<accounts.json>' --dry-run
node scripts/import-icost.mjs --user admin --file '<iCost.xlsx>' --accounts '<accounts.json>'
```

## 自动参考汇率

股票管理的 USD/CNY 与记账共用 `shared/foreign-exchange.js`，按 Finnhub → FRED → Yahoo 回退。记账从股票管理的本机私有配置读取 Finnhub Key，密钥不返回浏览器。CNY 固定为 1；USD/HKD/JPY/MYR/EUR/GBP/SGD 自动获取。Finnhub 用 USD 基准报价计算交叉汇率；FRED 用同日 DEXCHUS 与各币种 H.10 观测计算，EUR/GBP 的序列方向与其他币种相反，禁止跨日期混算。Yahoo 用原币/CNY 货币对兜底。数据为参考值，FRED 为日频观测，并非实时兑换成交价。

进入记账页面后台加载汇率，不阻塞账单。资产按有效参考汇率自动折算，统计与资产页面展示来源、数据日和获取时间。手动“更新参考汇率”使用 `bookkeeping:fx:edit` 权限；60 秒缓存合并并发请求与失败退避。自动结果按 userId 保存在现有 bookkeeping_settings 中，修改预算或手动值不会抹除它。自动失败时优先手动备用值，随后上次成功值，后者显示历史缓存标记。超过一小时未重新获取的数据、重启后更新失败的数据均标记历史缓存；无法获取且无备用值时明确显示缺失。浏览器返回的来源/状态不含供应商密钥或底层错误详情。

FRED 口径参考：[HKD](https://fred.stlouisfed.org/series/DEXHKUS)、[JPY](https://fred.stlouisfed.org/series/DEXJPUS)、[MYR](https://fred.stlouisfed.org/series/DEXMAUS)、[EUR](https://fred.stlouisfed.org/series/DEXUSEU)、[GBP](https://fred.stlouisfed.org/series/DEXUSUK)、[SGD](https://fred.stlouisfed.org/series/DEXSIUS)。

## 分类与资产管理

分类页以支出/收入分别维护一级与二级分类，支持图标、排序、重命名、二级分类移动、停用/启用、同类型同层级合并和未使用分类删除。首次访问从该用户现有账单建立目录，再补充基础分类；之后不会因刷新重新创建已经移除的目录。重命名/合并同步关联账单的分类文本，保留账单 ID、原始行、去重标识、历史标记和金额。一级分类合并携带子分类，同名子分类自动归并。停用分类在新记账选择器中隐藏，原账单可保留原分类继续编辑；导入仍保留原始分类。分类笔数涵盖所有日期、账本和币种。新手工账单须选择已维护的启用分类。

资产页支持名称/备注搜索、分组筛选、账户类型与图标、组内排序、归档/恢复和信用卡还款入口。分组可以新增、重命名、排序、合并或删除空组；分组变更不影响账户 ID、余额或历史账单。账户明细入口清除日期、货币等其他筛选，展示该账户的全部历史记录。归档只隐藏账户且禁止新增关联账单/余额核对，仍保留关联历史及余额；历史账单可继续编辑。是否计入净资产由 included 单独决定，归档不会自动排除资产。信用卡还款通过原有转账逻辑同时联动付款账户与信用账户，跨币种仍需明确到账额。

首次运行幂等添加账户 archived/sort_order/icon/account_type 列和 categories/groups/catalog_init 表，不改动金额字段；原信用分组账户初始化为信用卡类型。目录按 userId 隔离，分类管理使用 bookkeeping:categories:view/edit，资产操作沿用 bookkeeping:accounts:view/edit，还款同时要求 bookkeeping:entries:edit。重命名、移动、合并及排序均在 SQLite 事务中执行。仅本模块管理变更时部署 portal 即可。

回归验证：Node 22 运行 node --test portal/src/*.test.js，新增覆盖合并去重、导入标识、停用分类、归档账户、分组迁移、余额保持及跨用户/只读权限；浏览器验证 PC 和手机布局及实际保存操作。

## 趋势、消费分析与统计穿透

统计页和明细共用全部筛选条件；收支金额、分类排行、每日/月度行和折线数据点可穿透到明细，返回时恢复原筛选。净支出明细包含支出、已报销、退款、报销入账以及其他账单的手续费；累计结余点通过 through 截止日期筛选组成该点的收入/净支出记录。导出和分页沿用穿透条件，不仅依赖浏览器当前加载的 100 笔。

收支折线按 CNY 等效总计展示收入、净支出和累计账单结余，缺失日期/月补零。总结显示当前范围收支、最大支出分类及占比，可在完整月份范围下给出可调整分类减少 10% 的试行目标（全历史或未结束月份先引导核对大额、固定与一次性支出）、记录内收支缺口、预算提醒和相同范围上一完整月份的支出变化。本月未结束或已穿透到局部日期时不计算整月环比；局部分类、账本等筛选不把局部支出当作全部月预算消耗。建议不假设用户未记录的收入或消费能力。新权限 bookkeeping:analysis:view 同时在页面和 state API 控制趋势及建议，普通用户须由管理员授予。

资产走势在统计页和资产页仅展示一条 CNY 等效总资产曲线。以当前计入总资产账户的余额总额为终点，倒序撤销全部历史及新增账单的资产影响，计算历史日末净资产。历史导入记录参与分析，仍不改动真实账户余额或 affects_balance。内部转账双方都计入资产时抵消本金，保留手续费；跨币种明确到账额时分别按两端币种折算，历史缺少到账额则按等值 CNY 本金估算。转入/转出不计入总资产的账户按资产边界进出计算；未关联账户的收支按总资产变化估算，界面显示估算笔数。当前账户计入范围用于所有历史日期，无法记录的开户、销户、投资涨跌仍会影响反推精度。

收支走势、累计结余、分类统计、总结和统计金额统一使用账单日期对应的历史参考汇率折算 CNY；参考值不代表银行卡实际兑换成交值。货币筛选仍匹配原始账单币种，默认选择全部货币。穿透对应全部原始币种账单并保留当前原币筛选，账单行保持原币金额；其 CNY 总计与统计点一致。缺少任意相关币种汇率时不显示部分总计，明确提示待获取币种；更新参考汇率后重新计算全部图表。资产数据继续在 accounts:view 权限下返回，分析查看权限不单独授予余额。

账单、账户、预算和分类管理弹窗均支持点击外部关闭；在弹窗内留白处点击或从内部拖动到外部不触发关闭。验证包括完整 Portal 测试、PC/390px 手机浏览器、分类/曲线穿透金额核对、返回筛选恢复及两种弹窗外部点击。

## 历史汇率与范围筛选

明细/统计看板仅显示 CNY 汇总，默认原币筛选为全部货币；账单行仍保留原币及按账单日期历史汇率计算的 CNY 等效值和实际汇率观测日。HKD 使用 HK$、USD 使用 US$，JPY 使用 JP¥，SGD 使用 S$，MYR 使用 RM，避免歧义。

历史参考汇率取自 FRED 的美联储 H.10 日度序列，使用同日的 CNY/USD 及另一币种/USD 交叉计算；EUR/GBP 方向相反。周末、节假日或当期尚未发布数据时只向过去查找最近已发布观测，最长 14 天，不使用未来数据，也不把当前报价冒充历史报价。历史数据按 currency/date 保存在 SQLite 的公共 bookkeeping_fx_history 表，h10 元数据表用于六小时刷新及失败退避。历史源无法更新时使用已有历史观测，缺少相关币种观测则阻止不完整的 CNY 汇总并提示，不改变原始账单金额。来源说明：[Federal Reserve H.10 历史数据](https://www.federalreserve.gov/releases/h10/hist/)。

周/月/年/全部/范围选择器及前后期导航在明细、统计、资产页共用，开始/结束日期都包含。短范围按天绘图，长范围按月绘图；首尾不完整月份穿透时保持原始范围边界，返回统计恢复范围。资产重建使用全部账单以保持当前余额锚点，再截取选定范围；范围期末反推净资产与当前余额分别展示。范围变更不改写资产基准或原始记录。当前资产锚点仍以当前汇率折算，历史账单变化以各自日期的参考汇率折算；这是一条现金流反推曲线，未登记的投资收益、开户销户和外币存量重估仍会影响历史精度。
# QQ 指令记账

记账页右上角“QQ记账”用于生成10分钟有效的一次性绑定码，在机器人私聊发送 `绑定记账 绑定码` 完成绑定。QQ 唯一绑定一个 Portal 用户，网页解绑不会删除账单。需要 `bookkeeping:view`、`bookkeeping:entries:edit`、`bookkeeping:accounts:view` 和 `bookkeeping:qq:edit`，每次执行及重复回执都会检查账号与当前权限。

在此设置默认账户和别名（每行 `简称=完整账户名`），可选填允许记账的群号。默认仅私聊；群聊必须在发送人自己的允许群列表内且包含真正的 @机器人 消息元素。机器人按发送人绑定账号入账，群不是公共账本；群回执仅显示结果和编号，不返回账户余额、账单金额或备注。

```
记账 支出 35 餐饮 微信 备注=午餐
记账 收入 5000 工资 支付宝
记账 支出 120 HKD 购物 港币账户 日期=2026-10-10
转账 500 微信 到 支付宝
转账 700 人民币账户 到 美元账户 到账=100
撤销 完整账单编号
记账帮助
```

金额最多两位小数，币种默认取账户币种，账户省略时用个人默认账户，日期默认北京时间当前时刻。分类必须存在，可使用 `一级分类/二级分类`。备注空格用下划线。跨币种转账必须填写实际到账金额，参考汇率只用于 CNY 统计，不替代实际账户扣款/到账金额。支持收入、支出、退款入账、报销入账、已报销和转账/还款/借出/收回；不开放 QQ 余额调整或账户创建。撤销仅允许本人通过 QQ 创建的账单，恢复余额影响。

消息处理结果与账单在同一 SQLite 事务中持久化，使用机器人账号、消息场景、发送人和消息 ID 去重；回复成功后确认送达。重复上报不会重复入账，回复投递失败保留未确认结果。手动重新发送是一条新消息，若上一条超时或未收到回执，先在网页核对避免人为重记。当前使用 WebSocket 实时接收，掉线期间不保证历史消息补收。每个 QQ 每分钟最多处理10条指令。

部署：更新 portal 和 qq-bot 后执行 `node scripts/configure-qq-bookkeeping.mjs`，仅修改私有运行时配置并保留备份；启用 NapCat 的本机3001 WebSocket映射，array 消息格式和 Token，随后重启 NapCat 与 qq-bot。`/health` 的 `bookkeeping.connected` 应为 true。发送接口继续走原 HTTP3000；新增内部 Portal `/api/internal/bookkeeping/qq` 仅允许本机连接和现有通知服务 Bearer Token。不使用浏览器管理员 Cookie，不将发送人的 QQ 号直接作为 Portal 用户 ID，不自动绑定通知接收人。

## 账单位置

NapCat 位置消息按官方兼容说明以 JSON 上报，接收端解析 `com.tencent.map` 的 `meta["Location.Search"]`（name/address/lat/lng）、`Location.Show` 和标准 location 消息段；只读取卡片内的地址及合法坐标，不访问卡片 URL，不接受普通分享卡片伪装成位置。来源：https://napneko.github.io/develop/msg 。QQ分享位置来自用户主动选择，不能证明实际实时 GPS 所在地。

私聊可以先分享位置卡片，再在10分钟内记一笔，位置使用后立即清除。漏发位置的账单先正常保存，并提醒分享卡片补充或发送 `跳过定位`；在补齐或跳过前，下一条记账指令会明确拒绝入账，防止多个待补账单混淆。也可以在本笔指令中加 `定位=跳过`。超时后账单保留且不自动附带旧位置，可发送 `补充位置 完整账单编号` 再分享卡片。

群聊首次位置准备需要 `@机器人 记账定位`，随后10分钟内接受该发送人的位置卡片，再由 @机器人 记账指令消费；已有待补位置账单时可以直接分享卡片。未经准备且没有待补账单的群位置卡片静默忽略。定位上下文按机器人、发送人、私聊/群聊及群号隔离，绑定变更或解绑时清除，SQLite持久化，重启不丢失。补位置仅更新当前用户账单的 location，不重新保存金额或重算余额。也支持引用原记账指令的位置卡片；定位补充和重复上报使用原消息去重。群内回执不披露地址或坐标。

网页在打开“新增账单”时请求浏览器当前位置并反查地址，支持显式重新定位；编辑既有账单不自动改写原位置。需要 `bookkeeping:entries:edit` 和 `bookkeeping:location:edit` 权限。定位需 HTTPS（线上使用 https://saoyu.fun/bookkeeping/）及用户浏览器授权；HTTP公网IP入口明确提示需要 HTTPS。手填位置优先，关闭弹窗或切换编辑对象后忽略迟到结果。保存新增账单会等待正在进行的定位，整个过程最多12秒；拒绝、超时或不支持时允许无位置保存，地址服务失败保留合法坐标。

分类统计同时展示分类支出和分类收入。分类收入仅汇总“收入”类型，按账单日期历史汇率折算 CNY，展示金额、笔数及正向分类收入占比；手续费保持计入支出，退款、报销回款、转账和借款收回不列为收入。点击收入分类穿透到同范围的收入明细，返回统计恢复时间及币种筛选。历史汇率缺失时提示待折算，不展示不完整分类收入。
