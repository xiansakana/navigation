# QQ Codex 移动入口

QQ私聊与授权群指令通过已鉴权的NapCat WebSocket进入现有qq-bot，校验QQ白名单和Portal权限后，调用服务器已登录的Codex CLI。沿用CLI账号登录与代理，不另外配置模型API。参考 [Codex非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)。

此功能只通过Git同步代码、已跟踪的根目录及子目录`AGENTS.md`；不向电脑同步会话、任务状态、CLI登录缓存、数据库或上传资料。QQ自己的会话可以连续使用，也可显式新建。

## 使用

接受授权用户私聊，或在已配置群中真实@机器人后发送的`codex`、`/codex`前缀指令。未授权群、未授权发送人、没有@的群指令和普通聊天不会触发执行。私聊附件可直接登记。群聊附件必须同条真实@机器人，或先单独@机器人开启一次性接收窗口；未开启窗口的普通群图片、文件和上传通知均忽略，不登记、不回执。

```text
codex 帮助
codex 项目
codex navigation 检查知识库的最近修改，运行相关测试并修复问题
codex 继续上一项任务
codex 状态
codex 额度
codex 模型
codex 模型 模型ID
codex 强度 强度值
codex 附件
codex 清空附件
codex 结果
codex 停止
codex 同步 navigation
codex 新会话 navigation
```

新会话不会删除已有代码。任务按队列逐个执行，最多5个等待或执行中的任务。回复较长时分段发送，`codex 结果`可以重新读取最近结果。QQ回执失败会退避重试；极端情况下发送后落库前中断可能出现重复回执，但同一入站事件不会重复创建任务。

`codex 额度`（也支持 `codex 用量`、`codex /status` 或 `codex 还剩多少周额度和5h额度，啥时候重置`）通过服务器已登录的 Codex CLI App Server `account/rateLimits/read` 实时查询，不调用模型、不拉取或推送Git、不改变原QQ会话。可指定项目，例如 `codex navigation 额度`。查询沿用任务队列、权限和结果投递设置；有任务执行时需等待，`codex 结果`可重读查询结果。返回5小时及周额度的剩余百分比和北京时间重置时间，多额度池分别展示；接口未返回的窗口标为“未提供”。查询的是QQ服务器账号，不保证与电脑登录账号相同。仅查询，不兑换或重置额度。接口文档：[Codex App Server](https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt)。

## 模型与推理强度

`codex 模型`（或`codex 模型列表`）显示服务器当前可用模型、当前会话实际继承的模型和强度；`codex 模型 模型ID` 切换当前会话模型，`codex 强度` 查看该模型支持的强度，`codex 强度 high` 等命令设置对应强度。模型和强度取自CLI实时`model/list`，不硬编码。`codex 模型 默认` 恢复服务器继承，`codex 强度 默认` 清除强度覆盖；切换模型会清空原模型的强度覆盖，使用新模型的默认强度。设置只对当前Portal用户的当前私聊或当前群生效，保存在共享SQLite，网页与QQ共用。

设置指令不启动模型，不占用代码任务队列，也不消耗待处理附件。同一发送人同一会话内，切换设置和后续入站指令按接收顺序处理。代码任务入队时快照保存会话设置；执行时读取服务器默认值并校验模型、强度及图片支持，随后向CLI显式传入模型和强度（续接会话也使用相同规则）。因此修改会话选择不会更改已排队任务的选择；继承服务器默认的排队任务使用开始执行时的服务器默认值。完成回执显示实际模型和强度。

首页新增 `/codex-cli/` 管理模块，可查看服务器CLI版本、登录类型/套餐、账户额度、服务器默认模型/强度及QQ入口默认覆盖；可修改服务器Codex用户配置中的默认模型/强度，也可为自己的QQ私聊或已授权群设置独立选择。全局默认使用CLI `config/batchWrite` 原子写入并校验配置版本，保留其他配置和注释。页面不提供任意TOML、文件路径、令牌或登录缓存的编辑/下载。

权限目录为「首页→Codex CLI」：`codex-cli:view` 进入和查看状态，`codex-cli:usage:view` 查看服务器账户额度，`codex-cli:settings:edit` 保存服务器默认设置，`codex-cli:runtime:edit` 保存自己的QQ设置（另外需已有QQ执行授权）。普通用户与游客不会自动获得这些权限；管理员通配权限可用。QQ本身仍沿用既有所有者白名单与`qq-codex:execute`。CLI沙箱及审批策略仅显示；QQ保留非交互审批和私有配置的沙箱设置。

## 图片与文件

私聊可直接发送图片/文件，再发送 `codex 分析刚才的图片` 或 `codex 汇总这些表格并返回Excel文件`。群聊可在同一条消息中真实@机器人并附图片/文件；也可先单独@机器人（或@机器人发送 `codex 上传附件`），再于2分钟内上传下一条图片或文件。接收窗口仅属于该用户与当前群，收到首条附件后立即关闭；多条附件消息需逐条重新@。普通群图片、文件及 `group_upload` 通知在未开启窗口时一律忽略，不登记、不回执。上传通知与对应普通文件消息不会因窗口仍开启而重复登记。随后仍需@机器人发送处理要求，文件也可以与codex指令同条发送。`codex 取消上传` 关闭窗口，`codex 清空附件` 和新会话也会关闭窗口；旧消息时间早于开启窗口的上传通知不接收。文件名、链接、文件正文不会被当作指令执行。

待处理附件保存在共享SQLite，按Portal用户和群聊隔离，30分钟有效；下一条普通任务会原子领取本会话的附件。`codex 附件` 查看待处理列表，`codex 清空附件` 取消登记；查询额度、状态、结果、帮助及同步代码不会消耗待处理附件。新会话会清空当前会话的待处理附件。只读取文件名、链接和大小等元数据，执行任务时通过已鉴权NapCat接口刷新下载链接并落盘；文件过期或下载失败会明确报错。

每次最多6个文件，单个25MB、合计50MB；图片支持PNG/JPEG/WebP/GIF，以CLI视觉输入传入新会话或续接会话。附件及生成文件保存于服务器私有目录（默认是配置的`logDirectory`旁的`media/`，也可配置`codex.mediaDirectory`），不进入开发仓库或Git。按用户、群聊和任务分目录；运行时文件需纳入私有数据备份及磁盘清理，不能当作代码部署。

任务会告知模型专用输出目录。用户要求返回文件时，模型将最终文件放入此目录；外层只读取这个任务目录中的普通文件并保存内容校验快照，再通过NapCat返回。图片不超过10MB时以内嵌图片发送，其他文件走私聊文件或群文件接口。返回文件沿用既有群聊结果设置；切换为私聊后，尚未发送的群附件也改发私聊。每个附件独立持久化、失败重试，已成功的附件不会随其他附件重发。`codex 结果`可重新发送最近结果与生成文件。

不读取QQ事件提供的本机路径，不开放公网下载接口；下载检查QQ来源与公共IP并固定DNS结果，重定向逐次复查，禁止内网下载。返回文件禁止目录、符号链接、硬链接和跨任务路径。语音、视频消息暂不直接处理，可作为普通文件发送。QQ投递存在“已发送但未落库时进程中断”的小概率重复窗口，与文字回执相同。

## 通知管理中的群聊配置

打开 `/notifications/` 的「QQ Codex 群聊」区域，可直接勾选 QQ 默认目标、Tibo 和业务提醒中已保存的群号。相同群号会去重并标注来源，也可手动添加其他群号（最多20个）。选择完整结果发送到「私聊发起人」或「原群并@发起人」，点击「保存群聊配置」，立即生效。新增通知群不会自动获得 Codex 执行入口授权；取消全部选择并保存会关闭群聊入口，不影响私聊。机器人需要已加入该群；配置群号不会自动加群。

设置保存在共享SQLite的`qq_codex_settings`，只属于当前Portal用户。需要执行权限、查看设置权限`qq-codex:settings:view`与保存权限`qq-codex:settings:edit`，权限目录为「首页→通知管理→QQ Codex」。此页面不允许更改执行账号、项目目录或CLI凭据。API为Portal自有`/api/qq-codex/settings`，按登录身份取用户ID，并校验跨站写入。

默认完整结果私聊，群内仅显示接收和完成状态。选择原群时，群成员均可看到模型结果；关闭群结果后，尚未投递的完整结果改发私聊。移除群会阻止后续指令、领取和群回执，并停止该群正在执行的任务。重新添加群后可以续接原群会话。

会话、历史结果、状态和停止操作按「用户＋项目＋群」隔离，私聊原会话保持不变。群A的`codex 结果`不会读取私聊或群B历史；群内`codex 停止`只取消发送人当前群的任务。代码仍使用授权项目的同一个Git开发检出，并按原有全局队列串行执行。

## 私有配置

在`qq-bot/config.json`配置（权限600，不提交Git；公共设置接口不暴露或修改此段）：

```json
{
  "codex": {
    "enabled": true,
    "binary": "/usr/bin/codex",
    "proxyUrl": "http://127.0.0.1:17890",
    "sandbox": "danger-full-access",
    "defaultProject": "navigation",
    "timeoutMs": 7200000,
    "logDirectory": "/var/lib/qq-codex/logs",
    "allowedUsers": [{"userId":"Portal用户ID","qqId":"该用户QQ号","projects":["navigation"]}],
    "projects": {
      "navigation": {"directory":"/var/lib/qq-codex/projects/navigation","remote":"git@github.com:xiansakana/navigation.git","branch":"main"}
    }
  }
}
```

默认`enabled=false`、白名单为空、沙箱为`workspace-write`。当前服务器按所有者此前授权使用`danger-full-access`，仅绑定该所有者的QQ；允许的群也只接受该所有者发出的指令。Portal用户还必须启用并具备`qq-codex:execute`权限，位置为「首页→通知管理→QQ Codex→执行任务」；管理员通配权限可用，普通用户不会自动获得。每次接收、领取、执行心跳和结果投递都会检查授权。

复用`bookkeeping.wsUrl`（默认回环3001）和`napcat.accessToken`接收事件；Codex独立启用时无需启用记账。只新增一个消息分发处理器，不另开公网入口。qq-bot运行账号需要已登录Codex、可用Git远端凭据，以及共享SQLite访问权限。

任务、私聊及群聊会话ID、群设置、事件去重和待发送结果保存在共享数据库的`qq_codex_*`表中，按Portal `user_id`归属，群聊另外按`group_id`隔离。每个项目目录是服务端预置的授权配置，消息不能指定任意远端或目录。若为其他所有者开放，应配置独立项目检出和操作系统账号。

## Git行为

- 首次任务在独立目录克隆配置的分支；原有生产检出`/opt/navigation`不作为编辑目录。
- 开始前验证仓库根目录、远端、分支及已跟踪的根`AGENTS.md`，执行`fetch`与`merge --ff-only`。根/子目录规则随Git更新，CLI正常读取，不使用忽略规则参数。
- QQ任务产生的代码由Codex按项目规则测试、提交和推送；外层再次核验工作区干净、远端分支是本地HEAD祖先，再普通`push`，不会强推或自动覆盖并发提交。
- 全新会话遇到未提交修改或Git分歧会停止同步。原QQ会话可继续处理这些保留的修改，期间不强行合并；用户可要求它检查并解决分歧。未提交的电脑修改不会通过Git自动传输。
- 本地已提交并推送的修改，在下一次QQ任务拉取。QQ已推送的修改，本地`git pull --ff-only`取回；遇到分歧保留两端修改并人工决定合并。
- 任务默认不部署、不重启生产服务；只有QQ任务明确要求才按仓库`AGENTS.md`执行部署。

取消或超时会终止执行进程组，保留已有修改。服务重启中断的任务标记失败，不自动重放可能已发生的代码/运维操作；排队任务和待发送回执保留。失败后先查看`codex 状态/结果`，再决定是否继续。诊断仅落在私有日志目录，QQ不转发原始stderr或配置秘密。

## 部署与验证

QQ 文字回复在进入发送队列前统一转换为纯文本：移除 Markdown 标题、加粗及代码围栏，保留代码原文和网址；链接显示为“文字（地址）”，表格按行转换为“列名：值”。长回复优先在换行处分段，避免拆开 emoji。自动完成回执与 `codex 结果` 重发共用此处理；任务结果和网页历史保留原始 Markdown。模型提示也会要求 QQ 回复使用纯文本。仅更新此格式处理时部署 `qq-bot` 即可，无数据库迁移或默认模型设置变更。

按仓库流程推送、ECS干净拉取后，运行`bash scripts/ecs-update.sh --expected-sha <SHA> --only portal,qq-bot`。Portal包含新增权限定义。配置完成后重启qq-bot；不需要再部署一个工作器。

本服务器初次启用可运行`node scripts/configure-qq-codex.mjs`：仅当默认私聊目标已绑定启用的Portal管理员时创建授权，先克隆并检查代码/AGENTS，再备份旧配置、写入私有配置；不自动猜测或绑定其他QQ，也不会发送消息。已经启用时拒绝覆盖现有配置。之后执行`pm2 restart qq-bot`。

`/health`的`codex.enabled/running`表示入口配置与执行状态，`bookkeeping.connected`表示共用WebSocket是否连接。模型可用性需通过实际任务验证，不把启用开关当成模型连通证明。

使用与本机`portal/node_modules/better-sqlite3`匹配的Node版本运行`cd qq-bot && npm test`，以及Portal全套测试。覆盖真实WebSocket消息分发、白名单和权限、重复事件、取消、重启恢复、Git拉取/推送、AGENTS同步、并发分歧及未完成模型输出保护。
