# 资源管理

首页的「资源管理」入口指向 `/resources/`，指标接口为 `GET /api/resources/metrics`。
默认仅管理员拥有访问权；可在权限后台为其他登录用户授予 `service:resources:view`。
访客无法访问页面或接口，接口响应使用 `Cache-Control: no-store`。

## 指标

- 服务器：CPU 使用率、1/5/15 分钟负载、内存及可用内存、Swap、运行时间、文件句柄。
- 存储：文件系统容量、可用空间、使用率、inode，以及物理磁盘读写速率。
- 网络：物理网卡总吞吐、各接口吞吐、累计错误和丢包。Docker 虚拟接口不计入总吞吐。
- PM2：状态、CPU、内存、PID、线程、文件描述符、运行时间和重启次数。
- Docker：容器及镜像、状态/健康提示、CPU、内存与限额、累计网络和磁盘 I/O、进程数。

CPU 和吞吐来自相邻采样的差值，首次采样或计数器重置时不显示虚构的零值。
PM2 的 CPU 按单核 100% 计，服务器 CPU 使用率按全部核心归一化。
PM2 在线状态仅表示进程运行，不等同于业务接口健康。

## 采集与部署

采集使用 Node 系统接口、Linux `/proc` 与 `/sys`、已有 PM2 和 Docker；无需新增依赖或修改生产配置。
PM2 和 Docker 信息按固定字段投影，不返回环境变量、命令、密钥、日志路径或容器标签。
外部命令设定 8 秒超时，并发查看共享采集请求及 10 秒缓存。
页面可暂停刷新，切到后台停止轮询；趋势在内存中保留最近 120 次采样，门户重启后清空。
单个采集源故障时显示不可用提示，页面保留上次成功采样。

部署仅需更新 `portal`。验证命令为 `cd portal && node --test src/*.test.js`。
