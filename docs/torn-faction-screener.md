# Chain 监控页：帮派筛选 Tab

入口：`/torn-toolbox/chain/#factions`。页面分为“Chain 监控”和“帮派筛选”，配置、运行状态和数据独立。只使用官方 API，不抓取游戏页面，不发送 QQ/Slack 通知。

## 筛选定义

从 `/v2/faction/search?filters=notDestroyed,...&limit=100&offset=0` 分页读取符合 respect 范围的帮派；全部分页完成后，按 respect 升序、同 respect 按 ID 升序处理。未确认分页完整时不伪称全局排序完成。每次手动启动只处理设定批次数（默认 10，最多 50），再次启动继续下一批；同一天复用列表，重取列表按钮清除列表/结果但保留历史缓存。

对当前 Leader 的连续 networth 日快照，从旧到新计算下跌前已扫描最高值。只考虑当日值低于前一日的日期：

- 单日减少金额 = `前一日值 − 当日值`。
- 距高点减少金额 = `下跌前高点 − 当日值`。
- “仅单日”“仅距高点”“两者同时”分别按相应配置判断，阈值为正整数 Torn $，默认各 1000000000（10 亿），不按百分比；例如输入 500000000 表示减少 5 亿。
- 下跌当日及此后的任意日快照只要达到或超过该高点，这次事件即排除。取剩余符合条件事件中的最近一次。未恢复是相对**下跌前高点**，不是仅比较今天与高点；不会忽略中途曾恢复的情况。

用 Torn UTC 日历日期计算 A、B，C 使用当前 `days_in_faction`：

- A = 下跌日到本次扫描日的天数。
- B = Leader 最后活动日到本次扫描日的天数。
- C = Leader 在当前帮派的天数。
- 必须同时满足 `C >= A` 和 `minDifference <= A − B <= maxDifference`；A−B 上下限可空、可负，包含边界。默认下限 0、上限不限。

只确认 API **日快照**中可观察到的变化，不能证明日内没有短暂回到高点。“全历史”从注册后的第一个完整日快照开始；“最近 N 天”仅确认窗口内高点，不宣称全账户最高点。历史接口返回的是截至查询日期的数值，时间戳表示该数值最后更新的时间；更新时间早于查询日正常，连续日期重复同一时间戳和值不会产生新下跌。拒绝未来更新、时间倒退、同一时间戳不同值、变化日与更新时间矛盾、缺失及 Leader/归属变化，显示“待确认”。结果显示具体排除理由及下跌日、跌幅、峰值、A/B/C/A−B、样本范围。

## API 与运行量

所有接口要求 Public Key（自定义 Key 需包含相应权限），规格见[官方 OpenAPI](https://www.torn.com/swagger/openapi.json)：

1. `/v2/faction/search` 提供 respect、Leader ID/name 和分页链接；先读取完整列表，再排序。
2. `/v2/faction/{id}/basic` 用 `leader_id` 核对当前 Leader。
3. `/v2/user/{id}/profile` 提供 `last_action.timestamp`、`signed_up`、`faction_id`。
4. `/v2/user/{id}/faction` 提供 `days_in_faction` 并核对帮派 ID。
5. `/v2/user/{id}/personalstats?stat=networth&timestamp={TCT日零点秒数}` 每次获取一个日期，检查返回 `personalstats[].name/value/timestamp`。只请求总 networth，按查询日缓存有效的截至该日数值，并保留真实更新时间。
6. 长历史读取完后重新核对 Leader、归属、最后活动和入帮天数，避免长扫描期间人员变化导致错误判断。

历史数据不是一次调用返回的曲线：N 天需要 N+1 个日样本。无缓存时 10 位 Leader ×365 天约 3720 次详情请求，另加搜索分页，单独占用 40 次/分钟队列约需 93 分钟；全历史取决于注册年龄，可能更久。与 Chain 模块共用 Portal 的 1.5 秒串行队列，合计最多约 40 次/分钟，实际等待还包括其他模块。外部工具同样占用 Torn 用户配额，本进程无法协调外部用量。

逐日缓存和进度持久化；暂停/撤权/服务重启后手动继续，从尚未完成的帮派重新核验并复用历史。当天样本每轮重新请求；跨 Torn 日期立即停止，下次刷新当日列表，历史缓存继续复用。完成当日列表后不会自动反复重扫。API 密钥/限流等致命错误停止批次；其他单帮派错误显示待确认并继续下一帮派。全历史安全上限为单 Leader 10000 日，超出不猜测。

## 权限、数据与部署

需原有 `torn-chain:view`，并按需分配：

- `torn-factions:view`：查看 Tab、配置概要、进度及结果分页。
- `torn-factions:config:edit`：保存筛选条件及 Key。
- `torn-factions:control:edit`：启动/继续、暂停、重取列表。

权限完整路径为“首页 → Torn 工具箱 → Chain 监控 → 帮派筛选”。接入 Portal 个人数据策略，默认按用户隔离，写操作同源校验；后台每个请求前后复查账号、权限和模块数据策略。不会自动向普通用户或游客授予新权限。API 仅返回 `hasKey`，不回传 Key。保存新配置会等待当前请求取消后重置列表/结果，避免旧任务覆盖新配置。

共享 SQLite 自动创建三张表，均含 `user_id`：

- `torn_faction_scans`：配置及小体积扫描元信息。
- `torn_faction_rows`：每帮派结果/进度，按当前行更新，避免每个日样本都重写全量列表。
- `torn_faction_networth`：按 Leader ID、请求日缓存历史日样本及实际时间戳。

备份包括三表，并按凭据保护。只部署 `portal`，无新增进程或公网端口；部署不会自动启动扫描或产生通知。使用既有 Git/SHA 部署流程，数据访问策略目录自动注册该个人模块，未新增工具箱首页入口。

## 金额配置升级

旧百分比不能直接换算为固定金额。首次访问自动保留 Key、respect、A−B 等设置和历史缓存，将两个金额阈值初始化为 10 亿；清除按旧百分比产生的列表及结果，提示确认金额后重新启动。旧页面提交百分比字段会被拒绝并提示刷新，避免静默使用错误单位。
