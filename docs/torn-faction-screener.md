# Chain 监控页：帮派筛选 Tab

入口：`/torn-toolbox/chain/#factions`。页面分为“Chain 监控”和“帮派筛选”，配置、运行状态和数据独立。只使用官方 API，不抓取游戏页面，不发送 QQ/Slack 通知。

## 筛选定义

从 `/v2/faction/search?filters=notDestroyed,...&limit=100&offset=0` 分页读取符合 respect 范围的帮派；全部分页完成后，按 respect 升序、同 respect 按 ID 升序处理。未确认分页完整时不伪称全局排序完成。点击启动后按设定批次大小（默认 10，最多 50 个帮派）自动连续扫描；批次结束不暂停，直到列表全部完成、手动暂停或致命错误。networth 历史也连续处理，每 100 个日样本保存进度并让出事件循环，再自动续批，保证长缓存区间也能响应暂停；同一天复用列表，重取列表按钮清除列表/结果但保留历史缓存。

对当前 Leader 的连续 networth 日快照，从旧到新计算下跌前已扫描最高值。只考虑当日值低于前一日的日期：

- 单日减少金额 = `前一日值 − 当日值`。
- 距高点减少金额 = `下跌前高点 − 当日值`。
- “仅单日”“仅距高点”“两者同时”分别按相应配置判断，阈值为正整数 Torn $，默认各 1000000000（10 亿），不按百分比；例如输入 500000000 表示减少 5 亿。
- 下跌当日及此后的任意日快照只要达到或超过该高点，这次事件即排除。取剩余符合条件事件中的最近一次。未恢复是相对**下跌前高点**，不是仅比较今天与高点；不会忽略中途曾恢复的情况。

用 Torn UTC 日历日期计算 A、B，C 使用当前 `days_in_faction`：

- A = 下跌日到本次扫描日的天数。
- B = Leader 最后活动日到本次扫描日的天数。
- C = Leader 在当前帮派的天数。
- 必须同时满足 `C >= A` 和 `minDifference <= A − B <= maxDifference`；A−B 上下限可空、可负，包含边界。默认下限 0、上限不限。

只确认 API **日快照**中可观察到的变化，不能证明日内没有短暂回到高点。“全历史”从注册后的第一个完整日快照开始；“最近 N 天”仅确认窗口内高点，不宣称全账户最高点。N 可留空（包括接口的空字符串/null），留空自动使用全历史；填写 2–3650 的整数使用最近 N 天，无须另选模式。旧客户端 historyMode 配置仍兼容。历史接口返回的是截至查询日期的数值，时间戳表示该数值最后更新的时间；更新时间早于查询日正常，连续日期重复同一时间戳和值不会产生新下跌。拒绝未来更新、时间倒退、同一时间戳不同值、变化日与更新时间矛盾、缺失及 Leader/归属变化，显示“待确认”。结果显示具体排除理由及下跌日、跌幅、峰值、A/B/C/A−B、样本范围。

## API 与运行量

所有接口要求 Public Key（自定义 Key 需包含相应权限），规格见[官方 OpenAPI](https://www.torn.com/swagger/openapi.json)：

1. `/v2/faction/search` 提供 respect、Leader ID/name 和分页链接；先读取完整列表，再排序。
2. `/v2/faction/{id}/basic` 用 `leader_id` 核对当前 Leader。
3. `/v2/user/{id}/profile` 提供 `last_action.timestamp`、`signed_up`、`faction_id`。
4. `/v2/user/{id}/faction` 提供 `days_in_faction` 并核对帮派 ID。
5. `/v2/user/{id}/personalstats?stat=networth&timestamp={TCT日零点秒数}` 每次获取一个日期，检查返回 `personalstats[].name/value/timestamp`。从今天倒序查询：若最后更新时间落在 U 日，则 U 日至查询日均使用该值，下一次只查询 U−1 日。按日补齐并持久保存有更新时间依据的连续样本，以维持原有逐日跌幅、历史峰值与中途恢复判断；遇到已有缓存矛盾标为待确认，不覆盖证据。当日样本仍重新请求。
6. 长历史读取完后重新核对 Leader、归属、最后活动和入帮天数，避免长扫描期间人员变化导致错误判断。

扫描前先计算可能的下跌年龄区间：A 的下界为 max(0,B+最小差值)，上界为 min(C,窗口内最早可下跌日的年龄,B+最大差值)，未填边界不限制。只有区间为空才提前排除，完全不请求净资产历史；不会缩短高点历史，也不会因为较新的事件不满足身份条件而改选较老事件。身份时间无效仍标为待确认。

历史数据不是一次调用返回的曲线，N 天仍保留 N+1 个日样本，但不变区间不再逐日请求。固定测试中 1001 个日样本、两段不变区间只需 2 次历史调用；每天都变化的最坏情况仍需 N+1 次。提前排除和历史缓存继续减少请求，界面显示跳过的不变日期数。

可保存最多 10 个 Public API Keys（每行一个，亦支持逗号或空白分隔），保存时去重；填写新列表会替换原列表，留空的表单保留已保存 Keys，API 的 apiKeys:[] 可清空。旧 apiKey 单 Key 配置自动兼容。多个 Key 启动前使用 `/v2/key/info` 核验所属 Torn 账号，同账号只选一个代表 Key 轮转，不叠加额度。Portal 统一客户端会按 Torn 账号合并 Chain 和帮派筛选的 2 秒请求队列，每个账号约 30 次/分钟（另有初次 Key 核验）；不同账号独立队列，可分担扫描请求，整个进程额外限制请求启动间隔至少 100ms。请求按顺序执行并轮转账号，实际速度取决于延迟、变化数量和其他模块占用。

官方配额为每个 Torn 用户所有 Keys 合计 100 次/分钟：https://www.torn.com/api.html 。同一账号增加 Key 不会提速；只使用已获授权的账号 Keys。外部工具仍占用对应 Torn 账号配额，本进程无法协调外部用量。Key 无效、被禁用、暂停、权限不足或所属账号无法确认时，本次扫描跳过该 Key，保留配置并显示序号/原因；启动核验继续检查后续 Key，运行中失败重试当前请求，可使用已验证的同账号备用 Key，仍共享账号额度。所有 Key 均不可用才停止；再次手动启动会重新校验。IP 封禁或每日读取限额等全局/额度致命错误立即停止。分钟限流（错误 5 / HTTP 429）触发共享冷却门控；帮派筛选等待 65/130/260 秒或更长的 Retry-After，再用原 Key 自动重试，详见下段。Chain 监控仍保留停止后手动启动行为。

逐日缓存和进度持久化；暂停/撤权/服务重启后手动继续，从尚未完成的帮派重新核验并复用历史。当天样本每轮重新请求；跨 Torn 日期立即停止，下次刷新当日列表，历史缓存继续复用。完成当日列表后不会自动反复重扫。错误 5（账号请求过多）及 HTTP 429 进入可暂停的冷却等待，按 65/130/260 秒递增，优先遵守更长的 Retry-After；同一请求使用原 Key 重试，最多 3 次，持续限流后才停止并保留进度。IP 封禁（8/9）、每日额度等其他致命错误仍立即停止，不尝试换 Key 绕过；Key 自身错误按上段跳过；其他单帮派错误显示待确认并继续下一帮派。全历史安全上限为单 Leader 10000 日，超出不猜测。

## 权限、数据与部署

需原有 `torn-chain:view`，并按需分配：

- `torn-factions:view`：查看 Tab、配置概要、进度及结果分页。
- `torn-factions:config:edit`：保存筛选条件及 Key。
- `torn-factions:control:edit`：启动/继续、暂停、重取列表。

权限完整路径为“首页 → Torn 工具箱 → Chain 监控 → 帮派筛选”。接入 Portal 个人数据策略，默认按用户隔离，写操作同源校验；后台每个请求前后复查账号、权限和模块数据策略。不会自动向普通用户或游客授予新权限。API 仅返回 `hasKey`、`keyCount` 和核验后的有效账号数，不回传任何 Key 或所属账号 ID；保存配置和全部错误输出均隐藏完整 Key。保存新配置会等待当前请求取消后重置列表/结果，避免旧任务覆盖新配置。

共享 SQLite 自动创建三张表，均含 `user_id`：

- `torn_faction_scans`：配置及小体积扫描元信息。
- `torn_faction_rows`：每帮派结果/进度，按当前行更新，避免每个日样本都重写全量列表。
- `torn_faction_networth`：按 Leader ID、请求日缓存历史日样本及实际时间戳。

备份包括三表，并按凭据保护。只部署 `portal`，无新增进程或公网端口；部署不会自动启动扫描或产生通知。使用既有 Git/SHA 部署流程，数据访问策略目录自动注册该个人模块，未新增工具箱首页入口。

## 金额配置升级

旧百分比不能直接换算为固定金额。首次访问自动保留 Key、respect、A−B 等设置和历史缓存，将两个金额阈值初始化为 10 亿；清除按旧百分比产生的列表及结果，提示确认金额后重新启动。旧页面提交百分比字段会被拒绝并提示刷新，避免静默使用错误单位。
