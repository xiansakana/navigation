# 用户监控 · 出院前提醒

入口：Torn 工具箱 → 监控 → 用户监控。每个 Portal 用户独立配置、运行与存储；游客和授权共享范围可只读查看。权限管理中的路径为「首页 / Torn 工具箱 / 监控 / 用户监控」，配置、启停、清空及通知查看/保存/测试分别授权。

## 使用

1. 输入最多 100 个用户 ID 或 `https://www.torn.com/profiles.php?XID=...` 链接，每行一个。
2. 保存自己的 Public API Keys（最多 10 个），提前提醒默认 1 分钟，可设 0.1–1440 分钟。扫描间隔默认 15 秒，可设 5–3600 秒；API 账号请求间隔默认 2 秒，可设 1–60 秒。
3. 到「通知管理 → 业务提醒 → 用户出院」配置 QQ/Slack 开关、目标、@ 和测试。默认均关闭。监控页只配置监控条件，不设置投递目标。
4. 保存后点击启动用户监控。保存配置会停止本项监控，其他监控不受影响；停止不会清除历史。默认未运行，不会自动复制其他模块的 API Keys 或通知目标。

## 数据和提醒语义

使用官方 API v2 `GET /user/{id}/profile` 的 `profile.status.state` 和 `until`（Unix 秒），只在 `Hospital` 且出院时间有效时计算；不访问游戏内部页面接口。来源：[官方 OpenAPI](https://www.torn.com/swagger/openapi.json)。Public 权限即可，仍以实际 Key 的有效选择和权限为准。

当 `0 < until - now <= 提前分钟 × 60` 时记录提醒，并按中央通知配置投递。首次发现已在窗口中也提醒；已过出院时间或状态不明不补发、不推断出院。状态为 Hospital 但 until 已过去时页面显示「预计时间已到，等待 API 核验」。

每个用户/出院时间去重，存储在 SQLite `torn_user_monitors`；服务重启、配置修改和清空记录均保留去重。出院时间变化后按新的期限重新计算，因此延长住院可能产生新期限的一次提醒。提醒前每次均依据最新成功的 API 查询，不用旧的观察缓存直接投递。清空记录不重置去重；最近 200 条记录分页显示，去重保留最近 10000 个期限。

已知提醒节点会提前安排下一次核验，但不承诺精确提前一分钟：官方缓存、扫描用户数、请求排队、限流和通知延迟都可能影响时间。多 Key 按所属 Torn 账号与其他监控共享额度，同账号不叠加。失效 Key 跳过，所有 Key 失效或权限撤销停止；网络或限流在共享客户端冷却/有界重试后会在下一轮继续。

通知含用户名称/ID、预计出院 UTC 时间、当时剩余秒数和 profile 链接。记录区分渠道禁用、已提交渠道、投递失败；投递成功仅代表渠道接口接受，不代表 QQ 客户端必定收到。失败不自动重发历史，以免重复骚扰；保存记录与投递间不是分布式 exactly-once。

## 运行与验证

运行在既有 `torn-monitor-worker`，经 Portal 签名代理，同源、RBAC 和数据范围检查沿用其他监控。`torn_monitor_runs` 保存启停意图，worker 重启恢复此前运行且仍有权限的任务；停止的用户监控不恢复。

测试覆盖边界、首次窗口内发现、改期、提前出院、不明状态、失败重试、跨重启/清空去重、账号隔离、Key 隐藏、同源/RBAC/游客只读、中央通知编辑及 worker 进程恢复。使用模拟官方响应和本地通知，不发送真实 QQ 测试或攻击请求。
